For Cassandra:
==============

Note: Because the TenantLookAndFeel data model is changing with the following:

1. Dropping properties that are not being used.
2. Renaming of properties to better reflect their purpose.
3. Addition of new properties

With Cassandra, we can safely drop the columns that are no longer needed, but
we cannot rename non-primary key columns. There are 2 choices here:

1.  Create a new versioned table (_v2) with the correct names and all of the new columns,
    then migrate the data using a cqlsh script.
2.  Keep the existing table, add the new columns, but use the Datastax mapper to map the
    existing column names to the new names of the object model.

For this migration, we will choose option 2, even if there ends up being a slight drift
in the naming convention (Cassandra schema vs Object properties)

    smsallowpasswordresetotp = false,
    smsalertonpasswordchange = false,
    smsalertonmfadevicechange = false,
    smsalertonaccountstatuschange = false,
    smsalertonemailchange = false
WHERE systemid = <your systemid value>


update captcha_config
SET
    captchaenabled = false
